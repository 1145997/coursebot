# 整页任务清单重构（开发中，未发布）

## 历史基线

审查了 DSH 的 68 轮相关对话，重点核对了最后五轮的完整请求和回复，并对比 GitHub v1.9.8 与 DSH 本地 v1.10.3。

反复出现的问题：

- 把橙色待办数量解释为视频或测验类型；实际只能证明有待办。
- 把当前截图里的任务点数量当成整页视频总数，漏掉屏幕外的中间或最后一段。
- 滚动后复用旧坐标、旧时间，切换播放器后没有重新建立进度基线。
- 任务点为绿色时仍点击中央按钮，造成已完成视频重播。
- 视频控制栏隐藏和幻灯片静止引发误判；多个播放恢复入口相互切换暂停/播放。
- 改动缺少入口级验证，发生 Frame 类型错误、方法误删和仅短时运行就发布的问题。

## 验收场景

当前真实案例：一页三段，初始状态为「未完成、已完成、未完成」。必须先确定总数和各段状态，只操作第一、第三段；整页任务完成后，再从整页目录选择橙色待办。相同时长、相同封面和屏幕外位置都不能用来合并视频身份。

## 新模块

- `course_state.py`：与桌面输入无关的整页清单及单一决策器。通过页面身份和播放器顺序保存独立进度；所有播放动作共用冷却及次数限制。
- `accessibility.py`：Windows 浏览器整页可访问性树适配器。关联任务标记、播放器、时间和播放按钮；树读取失败、截断或任务状态未知时停止，不把部分结果报告为完整清单。
- `automation.py`：整页模式与旧截图播放路径互斥；现有测验识别仍保留。目录数字仅用于选择有待办的章节，进入后再识别实际任务类型。

## 发布要求

先验证完整真实流程，再 push/tag/release。当前版本为开发版；单元测试通过不能代替整页实测。真实页面的测试记录放在本地 logs 中，不将登录参数、原始聊天记录或 API Key 提交仓库。
